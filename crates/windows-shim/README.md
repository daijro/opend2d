# windows-shim / windows-core-shim

The `windows` crate is `#![cfg(windows)]` (empty off Windows), and `windows-core` / `windows-strings`
gate the pointer-string types and a few helpers behind `#[cfg(windows)]`. So the one COM
implementation in the ffi crates' `win/*` — written against those crates — would not build off
Windows. These two crates stand in for `windows` / `windows_core` on every platform (the ffi crates
depend on them under those names via Cargo `package =` renames):

- **`windows-core-shim`** (as `windows_core`): re-exports the real `windows-core`, plus (off Windows)
  the `PCWSTR`/`PWSTR`/`PCSTR`/`PSTR`/`BSTR` types, the `Free` trait, the `s!` macro and the
  `TypeKind`/`Param` impls that `windows-strings` only ships under `#[cfg(windows)]`.
- **`windows-shim`** (as `windows`): on Windows re-exports the real `windows` crate; off Windows
  provides `src/bindings.rs` — windows-bindgen output over `windows-core` — so `windows::Win32::…`
  resolves everywhere. One implementation, every platform.

## Regenerating `src/bindings.rs`

Generated by [`windows-bindgen`](https://crates.io/crates/windows-bindgen) 0.62.1 from its bundled
Win32 metadata, filtered to the closure the ffi crates reference (every interface `win/*` implements
plus referenced types). The filter set is `filter-roots.txt` (one `--filter` argument per line; the
four core graphics namespaces are whole so no method goes opaque, the rest are type-filtered). To
regenerate, run bindgen with those filters plus `--implement --no-comment`:

```rust
let roots = std::fs::read_to_string("filter-roots.txt").unwrap();
let mut args = vec!["--in".into(), "default".into(), "--out".into(), "src/bindings.rs".into(),
                    "--implement".into(), "--no-comment".into()];
for r in roots.lines().filter(|l| !l.trim().is_empty()) { args.push("--filter".into()); args.push(r.into()); }
windows_bindgen::bindgen(&args);
```

`CreateDIBSection` is deliberately excluded (its wrapper calls the Windows-only
`Error::from_win32`; it is reached only from `#[cfg(windows)]` code).

After regenerating, run `python3 -I fix-udt-return-abi.py`: windows-bindgen emits a **by-value**
`-> windows_numerics::Vector2` for the four D2D1_POINT_2F getters (GetStartPoint/EndPoint/Center/
GradientOriginOffset), which is mis-lowered on `x86_64-pc-windows-gnu` and wrong for real COM callers
(native d2d1 / TerraFX use the member ABI: a hidden result pointer as the second argument). The script
rewrites them to the out-param form windows-bindgen already uses for every Win32 POD struct return. It
is idempotent.
