# windows-shim and windows-core-shim

The `windows` crate is `#![cfg(windows)]`, so it is empty off Windows, and `windows-core` and
`windows-strings` put the pointer-string types and a few helpers behind `#[cfg(windows)]`. The
single COM implementation in the FFI crates' `win/*` modules is written against those crates, so it
would not build off Windows. These two crates stand in for `windows` and `windows_core` on every
platform. The FFI crates depend on them under those names through Cargo `package =` renames.

- `windows-core-shim`, used as `windows_core`, re-exports the real `windows-core`. Off Windows it
  also provides the PCWSTR, PWSTR, PCSTR, PSTR and BSTR types, the `Free` trait, the `s!` macro,
  and the `TypeKind` and `Param` impls that `windows-strings` only ships under `#[cfg(windows)]`.
- `windows-shim`, used as `windows`, re-exports the real `windows` crate on Windows. Off Windows it
  provides `src/bindings.rs`, which is windows-bindgen output over `windows-core`, so
  `windows::Win32::…` resolves everywhere. There is one implementation for every platform.

## Regenerating src/bindings.rs

The file is generated by [`windows-bindgen`](https://crates.io/crates/windows-bindgen) 0.62.1 from
its bundled Win32 metadata, filtered down to what the FFI crates reference: every interface that
`win/*` implements, plus the types they refer to. The filter set is in `filter-roots.txt`, with one
`--filter` argument per line. The four core graphics namespaces are included whole so that no
method becomes opaque, and the rest are filtered by type. To regenerate, run bindgen with those
filters plus `--implement --no-comment`:

```rust
let roots = std::fs::read_to_string("filter-roots.txt").unwrap();
let mut args = vec!["--in".into(), "default".into(), "--out".into(), "src/bindings.rs".into(),
                    "--implement".into(), "--no-comment".into()];
for r in roots.lines().filter(|l| !l.trim().is_empty()) { args.push("--filter".into()); args.push(r.into()); }
windows_bindgen::bindgen(&args);
```

CreateDIBSection is deliberately excluded. Its wrapper calls `Error::from_win32`, which exists only
on Windows, and it is reached only from `#[cfg(windows)]` code.

After regenerating, run `python3 -I fix-udt-return-abi.py`. For the four getters that return a
D2D1_POINT_2F (GetStartPoint, GetEndPoint, GetCenter and GetGradientOriginOffset), windows-bindgen
emits a by-value `-> windows_numerics::Vector2` return. That is lowered incorrectly on
`x86_64-pc-windows-gnu`, and it is wrong for real COM callers: Windows' own d2d1.dll and TerraFX
use the member ABI, which passes a hidden result pointer as the second argument. The script
rewrites these getters to the out-parameter form that windows-bindgen already uses for every Win32
POD struct return. It is idempotent.
